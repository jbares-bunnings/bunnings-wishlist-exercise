# Bunnings wishlist — code review exercise

Treat this repository **as if it were a pull request** you have been asked to review.

Your task is to **read the codebase and write up your review**: for each issue you notice, explain what is wrong (or risky), where it lives, and why it matters—**the way you would leave comments on a PR**, on different parts of the change.

You can focus on anything that would belong in a real review: correctness, bugs, security, performance, accessibility, structure, typing, naming, consistency, and maintainability. You do **not** have to fix the code unless you are asked to; the main deliverable is **your review and comments**.

Most of the UI code is in `src/BunningsWishlist.tsx`; mock product data is in `data/wishlist.json`.
